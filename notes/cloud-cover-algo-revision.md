## 二、U-Net 云边缘识别差 /「有云判无云」偏置

**根因不在模型，而在后处理。** 旧版先在小分辨率取 argmax，再把硬标签最近邻放大，
云缘的亚像素判断被整体丢弃。

| 后处理 | 云量 MAE(成) | 云类 IoU | 云区边界像素(越少越平滑) |
|---|---|---|---|
| 旧：256 argmax → 最近邻 | 0.144 | 0.8805 | 6848 |
| 新：三通道 logits 放大后 argmax | **0.138** | **0.8850** | **6052** |

模型本身的误差结构（`diag_bias.py` 实测）：

| 指标 | 数值 |
|---|---|
| 云内部召回 | 0.996 |
| 云缘 ±2px 带内召回 | **0.480** |
| 小于 10px 碎云召回 | **0.677** |
| 有云判无云(FN) / 无云判有云(FP) | 1.23（确实偏"漏报"） |

**经实测否决的方案**（避免后人重复走弯路）：

| 方案 | 结论 | 证据 |
|---|---|---|
| 光度增强重训 | 无改善 | 域偏移平均 MAE 2.255 成，劣于 v1 的 2.168 成；域内 IoU 0.9332→0.9265 |
| 推理前白平衡归一化 | 明显变差 | 灰度世界/蓝天锚定各档均劣于不归一化（最好 2.168 vs 最差 4.877 成） |
| 翻转 TTA | 无增益 | 同分辨率下指标完全一致，耗时翻倍 |

## 三、色比法：厚云/强对比漏检、暗云底识别差

**根因**：raw R−B 的绝对值随亮度缩放，厚云压暗画面时色差整体变小、阈值相对偏高；
且旧版有一条"直方图单峰就二值化到 0 成 / 10 成"的兜底分支，是造成"整幅云却报 0 成"的直接原因。

**新方案**：归一化红蓝差 `NRBD = (R−B)/(R+B)` + 谷深守卫 + 低饱和度补判。

| 指标 | 旧版 raw R−B | 新版 NRBD |
|---|---|---|
| 云量平均误差 | 2.830 成 | **0.399 成** |
| 云类 IoU | 0.497 | **0.823** |
| 多云档(5–8 成) MAE | 4.568 成 | **0.537 成** |

参数经 5 折交叉验证，五折各自独立收敛到同一组值，非过拟合。

**⚠ 实现要点（踩过的坑）**：`dipStat` 必须先对直方图做 5 桶滑动平均再取谷深。
直方图可能很稀疏（相邻像素映射到同一桶、个别桶为空），直接取单点最小值会把空桶误当"谷"，
导致守卫失效 —— 表现为**纯晴空被判成 59% 云量**。

## 四、不增大模型 / 不增加加载时间

- ONNX 4,426,863 B（4.43 MB），SHA256 与修订前**完全一致**；
- 参数量 1.11M 未变；
- `runAI` 内仍只有 **1 次** `session.run`，未引入 TTA；
- 色比法仍为逐像素四则运算 + 511 桶直方图，线性耗时。

## 复现方式

```bash
cd train
python prepare_data.py                     # 生成 data.npz（需 dataset/ 下有 WSISEG）
python eval_webpath.py                     # AI 后处理对照
python verify_newcolor.py                  # 色比法新旧对照
python cv_color.py                         # 色比法参数 5 折交叉验证
python diag_bias.py                        # 混淆矩阵 / 边缘 / 小云块召回
python bench_domain.py                     # 域偏移基准
python bench_wb.py                         # 白平衡归一化对照（结论：无效）
```

> 线上只需 `model/` 下的 ONNX 与 wasm 运行时。
