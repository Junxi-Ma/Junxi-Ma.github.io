## 一、为什么微信里打不开（重要）

**微信聊天窗口里点开 .html 文件，用的是「文件预览」内核，它不执行 JavaScript。**

这个页面几乎全部功能都靠 JS，所以预览模式下：页面样式正常显示，但按钮点了完全没反应。

这不是代码问题，**没有任何代码能绕过**。同一个文件：

| 打开方式 | 结果 |
|---|---|
| 电脑浏览器 | ✅ 正常 |
| 手机浏览器（Safari / Chrome） | ✅ 正常 |
| 微信里点 .html 文件 | ❌ 不执行 JS |
| **微信里点 https 网址** | ✅ **正常** |

**结论：必须把页面部署成一个网址，再把网址发到微信里。**

## 三、共享留言墙（让所有人互相看到留言）

**默认是本机模式**：留言、点赞、评论只存在访客自己手机上，别人看不到。
不需要任何配置就能用，适合先看效果。

要让全班互相看到，需要接一个云端数据库。用 Supabase，免费额度完全够用。

### 步骤 1：注册并建项目

1. 打开 [supabase.com](https://supabase.com) → 用邮箱注册（免费，不需要信用卡）
2. **New project**
   - Name：随便填
   - Database Password：随便设一个（记不记都行，页面用不到）
   - **Region：选 `Southeast Asia (Singapore)`**，离国内最近
3. 等 2 分钟左右，项目创建完成

### 步骤 2：建表（复制粘贴即可）

左侧菜单 → **SQL Editor** → **New query** → 把下面全部粘进去 → 点 **Run**

```sql
-- 留言表
create table if not exists wall_posts (
  id          bigint generated by default as identity primary key,
  name        text,
  content     text not null,
  photo       text,
  likes       int not null default 0,
  has_photo   boolean generated always as (photo is not null) stored,
  created_at  timestamptz not null default now()
);

-- 评论表
create table if not exists wall_replies (
  id          bigint generated by default as identity primary key,
  post_id     bigint not null references wall_posts(id) on delete cascade,
  name        text,
  content     text not null,
  created_at  timestamptz not null default now()
);

-- 点赞自增函数（多人同时点赞也不会互相覆盖）
create or replace function bump_likes(p_id bigint, p_delta int)
returns int
language sql
security definer
as $$
  update wall_posts
     set likes = greatest(0, likes + p_delta)
   where id = p_id
  returning likes;
$$;

-- 开放读写权限
alter table wall_posts   enable row level security;
alter table wall_replies enable row level security;

create policy "read posts"   on wall_posts   for select using (true);
create policy "write posts"  on wall_posts   for insert with check (true);
create policy "update posts" on wall_posts   for update using (true);
create policy "read replies"  on wall_replies for select using (true);
create policy "write replies" on wall_replies for insert with check (true);

grant execute on function bump_likes(bigint, int) to anon;
```

看到 `Success. No rows returned` 就是成功了。

### 步骤 3：拿到密钥

左侧菜单 → **Project Settings**（齿轮图标）→ **API**，复制两个值：

- **Project URL** — 形如 `https://abcdefghijk.supabase.co`
- **publishable key** — 形如 `sb_publishable_xxxxx`（旧版项目里叫 **anon public** key，是一长串 `eyJ...` 开头的字符，两种都能用）

### 步骤 4：填进 index.html（已完成 ✅）

**这一步已经帮你做好了**，`index.html` 顶部现在是：

```js
const CONFIG = {
  supabaseUrl: 'https://pimyumfvricwpigqlacv.supabase.co',
  supabaseKey: 'sb_publishable_Lz1UOc8oPtTOxv6shuYPYA__5bBUcE9',
  ...
```

如果以后换了 Supabase 项目，就把这两行替换成新的值，保存后重新上传。
（`supabaseUrl` 结尾**不要**带斜杠，也不要带 `/rest/v1`。）

打开留言墙，底部提示显示 **「已连接云端，所有人可见」** 就说明生效了。

## 四、你要改的内容在哪

**日常改内容不用碰代码**——学生名单、集体信、照片都已经改成读外部文件（见下一节）。
只有在文件读取失败时，页面才会回退到代码里的内置内容：

| 搜什么 | 改什么 |
|---|---|
| `const CONFIG` | 云端地址与密钥、三个内容文件的文件名、留言字数上限 |
| `const STUDENTS` | 学生名单和专属祝福（**仅在名单文件读不到时才用到**）|
| `const LETTERS` | 集体信，两封（**仅在 `信1.txt`/`信2.txt` 读不到时才用到**）|
| `const PINNED_MESSAGES` | 置顶留言，**已清空**。想让某条留言长期置顶，可按 `{ name:'姓名', time:'日期', content:'内容' }` 格式往里加（置顶留言不能点赞评论）|

代码里的数组都有示例，照着格式加就行。**注意每一项之间的逗号别漏。**

## 五、三个内容文件：名单 / 集体信 / 照片

这三块内容全部改成读外部文件，**改内容不用碰代码**。三个文件（夹）都要和 `index.html` 放在**同一级目录**上传。

### 1. 学生名单 —— `名单.csv`

用户输入姓名查询时用的就是这份数据。

- **格式：三列** —— A 列 = 姓名，B 列 = 教官一的祝福，C 列 = 教官二的祝福；第一行可以是表头（如 `姓名,教官一,教官二`，会自动跳过）
- 只填一列祝福也行：B 列有、C 列空，就只显示教官一那一封
- **祝福语支持多行**：Excel 单元格里按 Alt+Enter 换行即可
- **名单.csv**（推荐）：Excel 或记事本都能编辑，页面不需要加载任何外部库，最稳定。中文版 Excel 另存的 GBK 编码也能正确读取
- **名单.xlsx**：想要真正的 Excel 文件也可以。把 `CONFIG` 里的 `dataFile` 改成 `'名单.xlsx'` 一并上传即可（页面会按需从 CDN 加载解析库）
- 不想用文件时，把 `dataFile` 留空 `''`，回到代码里的 `STUDENTS` 数组

### 2. 集体信 —— `信1.txt` 和 `信2.txt`

点「查看写给全体同学的一封信」时，会先看到**两个信封**（教官一、教官二各一封），点开一封拆开看，合上后还能再拆另一封。两封信各自独立编辑，用记事本存成 UTF-8 或 GBK 都行。

开头可以写这几个标签（均可省略，省略就用默认值）：

```
[寄信人]教官一
[标题]写给同学们的一封信
[问候]亲爱的同学们：
[落款]教官一
[日期]二〇二六年九月
[印章]铁血

第一段正文……

第二段正文……

（段落之间空一行，空行分段）
```

- `[寄信人]` 显示在信封正面，是这封信来自谁；留空时按位置自动显示「教官一 / 教官二」
- `[印章]` 是落款处那枚朱砂印，**两个字最好看**，留空则不显示
- 标签之后按**空行分段**，一个空行一段
- 某一封的 txt 读不到时，自动用代码里的内置文本顶上

### 3. 集体相框 —— `photos` 文件夹

留言墙顶部的照片条。把军训照片放进 `photos` 文件夹：

- **命名要连续**：`1.jpg`、`2.jpg`、`3.jpg`……页面从 1 开始按顺序读，**遇到缺号就停止**
- 也支持 `.png`，如 `1.png`
- 照片会自动横向滑动，进入视野才加载
- 照片很多（超过 20 张）时，建议改用清单文件：`photos` 里随意命名，然后在根目录建 `photos.txt`，每行写一个文件名，并把 `CONFIG` 里的 `photosManifest` 改成 `'photos.txt'`
- 不放照片时，相框整块自动隐藏，页面不受影响

### 怎么确认都读取成功

打开页面时会连续弹出提示：**「名单已载入：N 位同学」**和**「信件已载入：2 封」**。
如果哪个文件读不到（比如忘传），页面会**安静回退**到代码里的内置内容——不影响使用，但这时改文件不会生效。

## 六、常见问题

**Q：留言墙显示「留言加载失败」怎么办？**
说明云端配置有问题。检查：URL 结尾有没有多余的斜杠、key 有没有复制全、SQL 有没有跑成功。页面底部的红色错误条会显示具体原因。

**Q：相框不显示 / 只显示前几张？**
两种原因：① `photos` 文件夹没和 index.html 放在同一级；② **照片编号不连续**——比如有 `1.jpg`、`2.jpg`、`4.jpg`，读到 3 找不到就停了。把编号连起来，或改用 `photos.txt` 清单。

**Q：Supabase 在国内访问会不会慢？**
会有波动。页面在云端请求失败时会给出提示，不会白屏。如果发现经常失败，可以考虑换成腾讯云开发，代码里的 `Store` 那一层是独立的，换起来不影响页面其他部分。

**Q：别人能乱发留言吗？**
publishable key 是公开写在网页里的，理论上懂技术的人可以绕过页面直接写入。对班级纪念页来说通常不是问题。如果担心，可以在 Supabase 后台随时把留言表清空。

**Q：怎么删掉某条留言？**
Supabase 后台 → SQL Editor，运行：

```sql
-- 删一条
delete from wall_posts where id = 1;
-- 清空全部（连评论一起删）
delete from wall_posts;
```

**Q：首页底部有个「版本 v8」和红色错误条，要删吗？**
确认一切正常后可以删。搜 `版本 v8` 删掉那一行 `<p class="ver">`；错误条平时不显示，留着也不影响，想删就搜 `errBar` 把对应的 `div` 和 `window.onerror` 那段 `<script>` 一起删掉。
